# 테스트 전략

## 리스크 기반 우선순위

아래 등급은 결함 실적이 아닌 사용자 영향, 데이터 변경 및 회귀 범위를 고려한 초기 QA 판단이다. 발생 확률은 아직 측정하지 않았으며 탐색 결과에 따라 순서를 조정한다.

| 우선순위 | 대상 | 리스크 / 우선 검증 |
| --- | --- | --- |
| P1 | F01/F02 인증 | 사용자 여정 진입 실패, 인증 상태 오인 / 정상·실패·로그아웃 |
| P1 | F04/F05 쓰기와 소유권 | 데이터 유실, 타인 데이터 변경 / CRUD 재조회·권한·실패 복구 |
| P2 | F03/F06/F07 | 사용자 상태 및 관계 불일치 / 수정·선택·해제·새로고침 |
| P2 | F08/F09 | 조회 누락/중복, 필터 혼선 / 필터·페이지 이동·빈 결과 |

## 설계 기법

| 기법 | 적용 이유 | 적용 방향 |
| --- | --- | --- |
| 상태전이 | 결과가 이전 상태와 동작에 의존함 | 비로그인→로그인→로그아웃, 글 생성→수정→삭제, 팔로우/즐겨찾기 선택→해제; 실패 시 이전 상태 유지와 금지 전이 확인 |
| 경계값 | 입력 및 목록의 한계에서 오류가 발생할 수 있음 | 정책 확인 후 길이 L-1/L/L+1 및 U-1/U/U+1; 페이지 크기 n에 대해 데이터 0/1/n-1/n/n+1건 |
| 오류추정 | UI/API 연결과 비동기 동작의 취약점을 탐색함 | 더블클릭, 응답 지연/실패, 새로고침, 삭제 리소스 재접근, 오래된 화면에서 수정, 토큰 누락/변조 |
| 동등분할 | 대표 입력을 선정해 중복을 줄임 | 유효 입력/필수 누락/형식 오류/중복 계정; 정확한 정책 확정 뒤 기대 결과 작성 |

실패 및 금지 전이는 성공 전이와 분리한다. 반복 팔로우·즐겨찾기의 처리 방식은 명세 확인 전 멱등성을 요구사항으로 단정하지 않는다. 응답 손실 뒤 재시도는 후속 조회로 실제 반영 여부를 확인하며 중복 생성 가능성을 관찰한다.

## 실행 방법

1. 환경과 구현체, 실제 API 주소를 고정하고 명세 차이를 기록한다.
2. 실행 ID를 붙인 계정/글/댓글을 준비한다. 계정 A/B 접근 가능 여부를 먼저 확인한다.
3. 수동 탐색으로 TC의 입력, 단계, 기대 결과 및 정책 근거를 확정한다.
4. Postman에서 인증·정상·오류 응답과 후속 조회를 검증한다.
5. UI와 요청/응답을 연결하고 새로고침 결과까지 대조한다.
6. 본인 생성 데이터 정리 및 정리 실패 내역을 기록한다.

서버 DB에 접근하지 않으므로 DB 저장 성공을 직접 증명하지 않는다. 네트워크 실패는 가능하면 브라우저 또는 Playwright의 요청 제어로 재현하며 공개 서버에 부하를 주는 방식으로 유도하지 않는다. 동시성 및 안정적인 페이지 경계 데이터가 필요한 테스트는 제어 가능한 환경에서 수행한다.

## 자동화 선정

Playwright는 로그인, 게시글 CRUD, 댓글 작성/삭제를 우선 후보로 둔다. 관계 기능은 계정 격리와 테스트 데이터 제어 가능 여부 확인 후 추가한다. 독립 데이터, 인증 상태 분리, 실행 후 정리, 사용자 관점 locator와 조건 기반 대기를 적용한다. 자동화 성공률을 위해 실패를 무조건 재시도하거나 고정 대기 시간을 늘리지 않는다.

실제 서버 연결 E2E와 응답을 제어한 UI 오류 테스트를 구분해 결과에 표시한다. Postman/Playwright는 아직 구성하지 않았으며 CI 도입도 추후 결정한다.

## 진입·완료 기준

- 진입: 대상 접근 가능, 명세/환경 기록, 핵심 기대 결과 확정, 테스트 계정과 정리 방법 확보
- 초기 사이클 완료 목표: 실행 가능한 P1 전체 수행, P1 실패의 재현/영향 분석, 수정분 재검증과 관련 회귀 수행
- 미해결 실패, Blocked, 미수행은 근거와 한계를 명시한다. 실행 불가를 Pass로 처리하지 않는다.
- 결과: TC ID, 실행일/환경, 입력/단계, 기대/실제 결과, Pass/Fail/Blocked/Not Run, 증거, 결함 ID 기록
- 커버리지: F01~F09별 설계·실행·통과·차단 수를 나누고 분모를 제시한다. 실행 전 수치를 성과로 기재하지 않는다.

핵심 회귀는 인증 → 게시글 생성/수정 → 댓글 → 즐겨찾기 → 삭제 및 재조회를 포함한다. 팔로우/피드와 프로필 변경의 작성자 표시 영향을 추가한다. 검증할 수 없는 환경 의존 항목은 별도 기록한다.
