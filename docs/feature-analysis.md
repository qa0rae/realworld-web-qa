근거: [공통 API 명세](https://docs.realworld.show/specifications/backend/endpoints/), [실행 API 문서](https://api.realworld.show/redoc). 확인일: 2026-10-05. 아래 경로는 공통 명세 기준이며 실행 환경의 Base URL과 대조한다.

| ID | 기능 | 세부 기능 / API | 검증 관점 |
| --- | --- | --- | --- |
| F01 | 회원가입 | `POST /api/users` | 필수 입력, 중복 계정, 성공 후 인증 상태 |
| F02 | 로그인 | `POST /api/users/login`, `GET /api/user`; 로그아웃은 UI 확인 필요 | 인증 성공/실패, 로그아웃 후 보호 동작 |

| F08 | 태그 | `GET /api/tags`, 게시글의 태그 및 목록 필터 | 태그 표시와 필터 결과 |
| F09 | 페이지네이션 | 목록/피드의 `limit`, `offset` | 처음/마지막/빈 페이지, 필터 전환 |

## 분석 관점

쓰기 동작은 UI 입력 → 요청 → 응답 → 화면 반영 → 새로고침/후속 조회 순서로 확인한다. 응답 성공만으로 저장 정합성을 판정하지 않는다. 실패 응답 뒤 성공 표시나 낙관적 UI가 남는지 확인한다.

회원가입·로그인·게시글·댓글의 필수 입력은 명세에서 확인하고, 길이·공백·문자 정책은 별도로 조사한다. 프로필 변경은 본인 화면과 작성자 표시의 회귀 영향을 확인한다. 게시글 제목 수정 시 URL 식별자 변경을 명세와 대조하고 연관 화면을 재조회한다. 팔로우와 즐겨찾기는 해제 및 새로고침을 포함한다. 페이지네이션은 테스트 동안 데이터 변화 여부를 기록한다.

## 확인 필요 사항

| 항목 | 확인 방법 | 확정 전 처리 |
| --- | --- | --- |
| 필드별 최소/최대 길이, 공백/문자, 중복 기준 | 실행 명세, UI 제약 및 공개 구현 코드 대조 | 숫자나 대소문자 정책을 임의로 확정하지 않음 |
| 타인 글/댓글 권한과 오류 코드 | 계정 A/B를 이용한 접근 및 명세 대조 | 검증 후보로 유지 |
| 데모 계정 간 데이터 격리 | 본인 테스트 계정 간 리소스 조회 | 공유 불가 시 관련 케이스 Blocked |
| 자기 팔로우, 반복 선택, 중복 태그 정책 | 명세/공개 구현 확인 및 탐색 | 탐색 관찰을 즉시 결함으로 단정하지 않음 |
| 삭제 후 연관 댓글/즐겨찾기 표시 | 본인 데이터 생성·삭제·재조회 | 내부 삭제 방식은 추정하지 않음 |
| 로그인 유지, 토큰 유효기간, 로그아웃 처리 | UI/Network 관찰 및 구현 자료 | 임의 만료시간을 가정하지 않음 |
| HTTP 오류와 오류 메시지 | 실행 API 문서와 실제 응답 대조 | 공통 명세와 차이를 기록 |

기능과 API 존재는 공개 자료 근거이며 권한 정책·오류 복구·경계 입력에 대한 검증 방향은 QA 설계 제안이다.
