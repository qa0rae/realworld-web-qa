# 결함 보고서 템플릿

복사해서 사용한다. 실제 발견된 결함 보고서가 아니다. 확인된 사실과 원인 가설을 분리하며 토큰·비밀번호·개인정보는 증거에서 제거한다.

## 기본 정보

| 항목 | 내용 |
| --- | --- |
| 결함 ID / 제목 | BUG-XXX / [기능] 조건과 문제를 한 문장으로 작성 |
| 보고일 / 보고자 | 작성 |
| 대상 URL / 구현체·버전 | 확인값 또는 확인 불가 |
| OS / 브라우저·버전 | 작성 |
| 연결 기능 / TC / 시나리오 ID | 작성 |
| 심각도 / 처리 우선순위 | 사용자 영향 / 수정 시급성의 근거를 각각 작성 |
| 상태 | 등록 / 분석 / 수정 / 재검증 / 종료 등 프로젝트 기준 |
| 재현 빈도 | 재현 횟수 / 시도 횟수 |

## 사전조건 및 테스트 데이터

- 로그인/권한/기존 데이터 상태:
- 비식별화한 테스트 계정 별칭, 리소스 식별자 및 입력값:
- 네트워크/요청 제어 조건:

## 재현 절차

1. 시작 화면과 사전조건을 설정한다.
2. 정확한 입력값과 동작을 기록한다.
3. 문제가 발생하는 단계와 확인 방법을 기록한다.

## 실제 결과

화면 표시, HTTP 상태/응답, 후속 조회에서 관찰한 사실을 기록한다.

## 기대 결과와 근거

예상 동작과 명세 URL/항목/확인일을 기록한다. 근거가 불명확하면 정책 확인 요청으로 구분하며 확정된 결함으로 단정하지 않는다.

## 영향 범위

영향받는 사용자/조건, 데이터 변경 여부, 반복 가능성, 우회 방법, 관련 회귀 기능을 기록한다. 관찰한 범위와 추가 검증이 필요한 범위를 구분한다.
